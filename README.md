# Инженерный помощник

Локальное desktop-приложение: отвечает на вопросы по реестру оборудования
и технической документации организации. Работает без интернета на месте установки,
кроме вызова LLM.

---

## Как это устроено

```
вопрос пользователя
        │
        ▼
   router.py ──── определяет тип вопроса
        │
        ├─ «сколько», «что менять»  ──►  registry_query.py
        │                                считает по Excel напрямую,
        │                                LLM чисел не выдумывает
        │
        └─ «как обслуживать», прочее ─►  retriever.py
                                         BM25 + вектор → RRF
                                              │
                                              ▼
                                    parent_store.py
                                    (фрагмент → родительский блок)
        ┌─────────────────────────────────────┘
        ▼
  router_client.py  ──►  RouterAI (OpenAI-совместимый API)
        │
        ▼
     ответ + таблица реестра + найденные фрагменты
```


## Структура

| Файл | Назначение |

## Данные

Две коллекции ChromaDB в одном хранилище — намеренно разделены:

- `equipment_docs` — реестр организации, собирается `build_index.py`;
- `user_docs` — что загрузил пользователь через интерфейс.

Смешивать нельзя: если пользователь зальёт мусор, основную базу это не тронет,
и её можно чистить одной кнопкой.

Родительские блоки лежат в `data/chroma/parents.db`, история — в
`data/history.db`.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # вписать ключ RouterAI

.venv/bin/python build_index.py    # индексация (нужна один раз)
.venv/bin/python run_app.py        # приложение + трей
```

Разработка без трея:

```bash
.venv/bin/uvicorn app.main:app --port 8000 --reload
```

## Особенности реализации

**PDF с битым текстовым слоем.** Коррекция кодирования в `pdf_text.py` исправляет ошибки типа `Îñíîâíûå ñâåäåíèÿ` и имена глифов.

**MinerU плодит процессы.** OCR-воркеры переживают родителя. `do_parse` вызывается напрямую, без HTTP-сервиса.

**Родительские блоки хранятся отдельно.** В `parent_store.py` (SQLite), не в метаданных ChromaDB.

**e5 требует префиксов.** При эмбеддинге добавляются `query:` и `passage:`; в `documents` хранится чистый текст.

**Локальные запросы и системный прокси.** При `http_proxy` в диапазоне `127.0.0.0/8` используется `trust_env=False`.

## Защита от галлюцинаций

Система ограничивает выход модели в контекстах, где спекулировать нельзя:

| Сценарий | Решение |
|---|---|
| Вопрос не про оборудование | Промпт: отказ с напоминанием о роли |
| Оборудования нет в реестре | Запрет подменять похожим |
| «Сколько всего X» | Считается по Excel, не моделью |
| Ложная предпосылка | Запрет подтверждать без данных в контексте |
| «Можно ли ставить 40А вместо 16А» | Инженерные заключения запрещены |
| Регламент ТО | Только дословно из документации |
| Опечатки в артикулах | Нормализация до канонического написания |
| «А сколько их?» | История последних обращений в контексте |

`temperature=0.1` — ответ придерживается фактов, а не формулировок.

Проверка: `.venv/bin/python tests/test_questions.py` (требует поднятого приложения).
Тесты проверяют поведение: наличие отказов, корректность подсчётов,
отсутствие типовых выдумок вроде «смазать контакты».

## Сборка exe

Собирается на Windows, кросс-компиляция невозможна.

```powershell
.venv\Scripts\pip install pyinstaller
.venv\Scripts\python build\prepare_bundle.py
.venv\Scripts\pyinstaller build\app.spec
```

Результат — `dist\Инженерный помощник\`. Рядом с exe кладутся `.env`
и папка `data` с базой и реестром.

Подробности: `build/README.md`.
